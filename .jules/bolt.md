## 2024-05-24 - Database I/O Bottleneck on IPC Calls
**Learning:** Found a critical performance anti-pattern in the Electron main process where the entire JSON database (`notes_data.json`) was being read from disk and parsed on *every single* IPC request (like getting all notes, or getting a note by ID). This makes operations slower and slower linearly as the local database grows, creating a massive bottleneck.
**Action:** Implemented an in-memory `dataFileCache` that is lazy-loaded on the first read and updated immediately during any write operation. This changes database reads from blocking $O(disk)$ operations to instantaneous $O(1)$ memory access, making the UI much more responsive. Future JSON-based file databases in this architecture should always use an in-memory cache synchronized with disk writes.
